# コメントの書き方

## 原則

コメントに書いてよいのは 2 つだけ。

1. **今のコードが何をするか**
2. **コードを読んでも分からない「なぜ」**（外部仕様、制約、意図的に不自然な選択）

それ以外は、書いた瞬間から腐り始める。腐ったコメントは無いより悪い。読んだ人が
それを信じて判断するからだ。

## 書いてはいけないもの

### 1. タスク番号・チケット番号

`YOSUKE-123` / `#123` / `TODO(YOSUKE-115)` / 「issue 42 参照」/ `FIXME(YOSUKE-99)`

なぜ書かないか:

- **issue は閉じる。** 閉じた番号を後から見ても、なぜ今のコードがこうなっているかは分からない。
- **リポジトリの外への参照になる。** clone しただけの人（数年後の自分を含む）は解決できない。
  トラッカーを移行したら全部ただの文字列になる。
- **commit と PR に既に残っている。** 二重に書くと、片方だけが古くなる。

代わりにどうするか:

- **未完成の実装** — コメントに TODO を残さず、Linear の issue にする。コードには
  「今どう振る舞うか」だけ書く（例: まだ 501 を返すこと）。読む人が困るのは
  「いつか誰かがやる」ではなく「今これを呼ぶと何が起きるか」が分からないこと。
- **理由を残したい** — 番号ではなく、理由そのものを書く。

```go
// NG: 番号を見に行かないと何も分からない
// TODO(YOSUKE-115): implement room join, fan-out and disconnect handling.

// OK: 今の振る舞いを書く
// ルームへの参加・配送・切断はまだ実装しておらず、501 を返す。
```

### 2. 過去の実装との比較

日本語: 従来 / 今まで / これまで / 以前 / 前回 / 旧〜 / 変更前 / 修正後 / 置換 /
〜に置き換えた / 新しく〜 / 従来通り
英語: previously / formerly / used to / instead of / replaces / no longer /
same as before / new implementation

なぜ書かないか: **実装が次に変わった瞬間に嘘になる。** レビュー時点の一時的な文脈が、
そのままコードベースに残り続ける。変更の経緯は git log と PR にある。

```go
// NG: 差分の説明になっている
// 従来は sync.Mutex を使っていたが、ここでは sync.RWMutex に置換した。

// OK: 現在の制約を根拠にしている
// 参加者の読み取りが書き込みより圧倒的に多いため RWMutex を使う。
```

### 3. 「〜と同様」という他所への参照

「matching と同様」/「〜と同じロジック」/ same as / similar to

なぜ書かないか: **参照先が変わっても、このコメントは変わらない。**「同じ」だった事実は
誰にも気づかれないまま嘘になる。同じであることが本当に重要なら、コメントで宣言するのではなく
共通の関数や定数にして、コードの側で同じにする。

## どこに書くか

コメントに書きたくなった内容の行き先。

| 書きたくなった内容 | 行き先 |
| --- | --- |
| なぜこの設計を選んだか、何を捨てたか | ADR（`docs/adr/`）→ `adr` skill |
| これからやること、未完成の部分 | Linear の issue |
| 何をどう変えたか | commit message / PR |
| 外部仕様・法規制・コスト制約に由来する不自然さ | コメント（制約そのものを書く） |
| コードを読めば分かること | 書かない（命名で解決する） |

## ADR への参照は書いてよい

`docs/adr/0003-use-air-for-hot-reload.md` のような ADR は指してよい。issue 番号との違いは、
**リポジトリの中にあって、clone すれば読めて、閉じないこと**。制約や却下した代替案を
コメントに毎回書き写す代わりに ADR を指せば、コメントを短く保てる。

```go
// 予算上限のため固定台数構成とし、オートスケールしない。詳細は docs/adr/0004-fixed-instance-count.md。
```

## 書かない選択

適切に命名すれば消えるコメントは、コメントではなく命名で解決する。
コメントの数を増やすことが目的ではない。

## 自己チェック

コミット前に引っかかりがないか見る。文字列リテラルにも当たるので、出力は目で確認する。

```bash
grep -rnE 'TODO|FIXME|HACK|XXX|YOSUKE-[0-9]+|従来|以前|これまで|今まで|前回|変更前|修正後|置き換え|と同様|と同じ|previously|formerly|used to|instead of|no longer|same as' --include='*.go' --include='*.ts' --include='*.tsx' . | grep -v node_modules
```
