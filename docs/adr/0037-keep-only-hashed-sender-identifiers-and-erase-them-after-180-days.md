# ADR-0037: 発信者情報はハッシュ値だけを持ち、参加から 180 日で消す

- ステータス: Accepted
- 日付: 2026-10-08
- 関連 issue: YOSUKE-142

## 文脈

- 基本設計書 3.4 は、発信者情報を一定期間保存し、裁判所の命令などに対応できる体制を持つことを求めている。
- 保存しているのは、`conversation_participants` の `ip_hash`（`SESSION_IP_HASH_SECRET` を鍵にした
  HMAC-SHA256）・`device_fingerprint`・`joined_at` と、メッセージの送信日時。生の IP アドレス、ポート番号、
  User-Agent は保存しておらず、ALB のアクセスログも取っていない。
- 公開済みのプライバシーポリシーは「IP アドレスはハッシュ値でしか保存しない」と約束している。参加記録の
  保管期間は書いていない。
- 日本には、通信記録の保存をサービス提供者に義務づける法令が無い。保有していない情報は「保有していない」と
  回答すればよい。
- 開示の請求者は IP アドレスを知らないから請求する。ハッシュ値を開示しても、接続プロバイダへの次の請求には
  つながらない。生の IP アドレスがあっても、ポート番号が無ければ携帯回線（CGNAT）の契約者はほぼ特定できない。
- 会話はマッチングした相手にしか届かない。情報流通プラットフォーム対処法の開示の請求は「不特定の者に受信される
  通信」を前提にしているため、本サービスがその対象になるかは確かでない。現実に届きうるのは、捜査機関からの
  照会や令状のほうになる。
- 費用を最優先にしている。運営者は 1 人で、データベースには SSM のポートフォワードでしか入れない。
- IPv4 のアドレスは約 43 億通りしかない。鍵を持つ者なら、すべてのアドレスのハッシュ値を計算すれば
  `ip_hash` から元のアドレスを求められる。

## 決定

生の IP アドレスは保存せず、保有するのは `ip_hash`・`device_fingerprint`・日時だけにする。参加者の識別子は、
retention バッチで参加から 180 日（6 か月）経ったら NULL にする。通報のあった会話の参加者の分は残す。
開示の請求・命令・照会には、`scripts/disclosure.sql` で 1 つの会話の記録を読み出して回答する。
`SESSION_IP_HASH_SECRET` は変えない。

## 検討した代替案

### 案A: 生の IP アドレスとポート番号を暗号化して別のテーブルに 90 日置く

開示で役に立つ情報が残る。一方で、公開済みのポリシーの改定、暗号化の鍵の管理、漏れたときの影響の拡大を
引き受けることになる。そのうえ、本サービスに開示の請求が届くかどうか自体が確かでない。費用優先の方針に対して
得るものが少ない。

### 案B: ALB のアクセスログを S3 に出す

コードを変えずに、IP アドレス・ポート番号・User-Agent・日時が残り、S3 の費用も月に数セントで済む。しかし、
「IP アドレスはハッシュ値でしか保存しない」という公開済みの約束に反する。ログの行を会話に結びつける仕組みも
別に要る。

### 案C: 参加記録の識別子を消さない

作業が要らない。しかし期限の無い保管になり、設計書の「90 日〜6 か月を目安に削除」とも合わない。ポリシーに
期間を書けない。

### 案D: User-Agent も保存する

端末の特定の手がかりになるのは `device_fingerprint` のほうで、User-Agent は同じ機種の利用者の間で重なる。
開示の役に立つ範囲に対して、保有する情報が増えるだけになる。

## 影響

- 開示できるのは、会話の参加と送信の日時、`ip_hash`、`device_fingerprint`、メッセージ、制裁の記録だけになる。
  IP アドレスそのものは開示できない。請求者が IP アドレスを示したときは、同じ鍵でハッシュ値にして照合できる。
- `SESSION_IP_HASH_SECRET` を変えると、それまでのハッシュ値と照合できなくなり、`ip_hash` にかけた制裁も
  効かなくなる。鍵が漏れたときは、照合と制裁を失うことを承知のうえで変える。
- ポリシーは「鍵を持たない人にはハッシュ値から IP アドレスを知ることはできない」と書く。鍵を持つ運営者には
  IPv4 のハッシュ値を戻せるので、「元に戻せない」とは書かない。
- 参加から 180 日を過ぎた、通報の無い会話の参加者には、会話を指定した BAN をかけられなくなる。
- 抽出したことは、アプリではなく CloudTrail の `StartSession` と `GetSecretValue`（90 日分は無料で残る）と、
  手順書の対応記録に残る。抽出が増えてアプリでの監査が必要になったら、管理 API の読み出しに切り替えることを
  検討する。
- 開示の請求が実際に届き、ハッシュ値だけでは回答にならないことが続いたら、案A を検討し直す。そのときは
  ポリシーの改定と、利用者からの同意の取り直しが要る。
