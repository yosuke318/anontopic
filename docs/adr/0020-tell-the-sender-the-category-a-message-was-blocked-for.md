# ADR-0020: ブロックした理由は分類までを送信者に返す

- ステータス: Accepted
- 日付: 2026-09-19
- 関連 issue: YOSUKE-130

## 文脈

一次フィルタで止めたメッセージは部屋に流さず、送信者にだけ `blocked` を返す
（[ADR-0018](0018-record-the-messages-the-filter-blocked.md)）。止めたときは、規約違反である
ことを理由と合わせて送信者に示す（YOSUKE-130）。

判断に効く事実。

- 辞書の語には `category`（`meetup` / `dating` / `sexual` / `contact` / `solicitation`）が
  既にあり、利用規約の禁止行為（設計書 3.2）の区分とほぼ対応している
  （[ADR-0004](0004-ng-word-dictionary-in-database.md)）。
- 辞書は誤検知を含む。誤って止められた利用者には、何が問題とされたのかが分からないと
  言い換えようがない。
- 一方で、止めた語やパターンをそのまま返すと、どこまでなら通るかを 1 通ずつ試せてしまう。
- 閲覧者（同じ部屋の他の参加者）には、止めたメッセージがあったこと自体を伝えていない。

## 決定

`blocked` の error に、止めた理由を `ng_words.category` の値で `reason` として付ける。外部連絡先の
パターンに当たったものは `contact` とする。当たった語・パターン・位置は返さない。画面は分類ごとに
「利用規約で禁止しているため送信できない」旨と、禁止事項のページへのリンクを出す。
閲覧者には何も出さない。

## 検討した代替案

### 案A: 理由を付けず、すべて同じ文言にする

回避の手がかりを一切与えない。ただし連絡先・待ち合わせ・性的表現のどれとされたのかが
分からず、誤検知で止められた利用者が言い換えられない。規約違反の理由を示すという
要件も満たせない。

### 案B: 当たった語やパターンを返す

誤検知の言い換えが一番しやすい。ただし通る書き方を探す道具になる。止めた語は
記録（ADR-0018）から運営が確認できるため、利用者に返す必要はない。

### 案C: 閲覧者にも「規約違反のメッセージが止められた」と出す

相手が連絡先を聞き出そうとしていることが閲覧者に分かる。ただし誤検知でも相手が違反者の
ように見え、止められた側だけが不利になる。通報とブロック（ADR-0016）の判断材料には、
閲覧者が実際に読んだものだけを使う。

## 影響

- 分類の値は外部インターフェース（`docs/asyncapi.yaml`）の一部になる。`ng_words.category` に
  値を足すときは、画面の文言も足す。画面は知らない値を理由なしとして扱い、汎用の文言を出す。
- 分類までは分かるため、同じ分類の中で書き方を変えて試すことはできる。繰り返し止められた
  送信者は記録（ADR-0018）から数えられるので、試行が目立つようなら通報対応の側で制限をかける。
- 辞書を読めていないために止めたもの（`ErrNoDictionary`）は理由を付けず、`unavailable` を返す
  現在の扱いのまま。
