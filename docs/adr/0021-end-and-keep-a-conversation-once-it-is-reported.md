# ADR-0021: 通報を受けた会話はその場で終わらせ、保持対象にする

- ステータス: Accepted
- 日付: 2026-09-21
- 関連 issue: YOSUKE-131

## 文脈

通報の受け口（[ADR-0015](0015-report-a-conversation-rather-than-a-participant.md)）は
`reports` に行を足すだけで、会話そのものには何もしていなかった。YOSUKE-131 で次を決める必要がある。

- 通報された会話を、保持期間（90 日）の削除から外す。`conversations.is_flagged` がその印で、
  削除バッチはこの列を見て除外する（設計書 4.2）。
- 通報の対象になったメッセージを `messages.moderation_flag = 2`（通報あり）で区別する。
  ただし通報は会話単位で、どの発言が問題だったかを通報者は指定しない（ADR-0015）。
- 通報後の即時対応として、会話を終わらせ、相手をブロックする。
- `conversations` と `messages` への書き込みは `chat` が持つ
  （[ADR-0010](0010-split-the-conversation-tables-by-lifecycle-phase.md)）。`report` から
  直接 UPDATE すると、CONTRIBUTING.md のモジュール間の依存ルールに反する。
- ブロックはブラウザの中だけで持つ（[ADR-0016](0016-block-a-participant-in-the-browser-only.md)）。
  相手を指す安定した識別子は無い。

## 決定

通報を受け付けたら、`report` が次の順に処理する。会話への書き込みは `report` が宣言する
`Conversations` インターフェース経由で `chat` に依頼し、`cmd/server/main.go` で配線する。

1. `reports` に記録する（同じ通報者の 2 回目は何もしない）。
2. `chat` が 1 トランザクションで `is_flagged = true` にし、**通報者以外の参加者が送った
   `moderation_flag = 0` のメッセージ**を `2` にする。フィルタが判定済みの `1` は上書きしない。
3. `chat` が会話を `end_reason = reported` で終わらせ、終わらせたときだけ部屋に `ended` を流す。
   既に終わっていた会話は元の終了理由のまま残す。

どの手順も繰り返して安全なので、途中で失敗した通報はクライアントが送り直せば完了する。

通報した人の画面では、残りの参加者を全員ブロックする。ブロックは ADR-0016 のとおり
ブラウザの中だけで持つ。他の参加者の画面には「参加者から通報があったため、会話は
終了しました。」と出す。

ADR-0010 の表に次の 2 つを足す。`chat` は通報を受けた会話について `conversations.is_flagged`
と `messages.moderation_flag` を UPDATE する。

## 検討した代替案

### 案A: 会話のメッセージをすべて 2 にする

実装は最も単純。ただし通報者自身の「やめてください」のような発言まで「通報あり」になり、
将来 AI 判定を通報された発言に限る（要件定義書 第4章）ときや、繰り返し違反を数えるときに
被害者の発言が混ざる。通報者のトークンは `reports` に既にあるので、除外は条件 1 つで済む。

### 案B: メッセージには印を付けず、`is_flagged` だけ立てる

保持の目的は `is_flagged` で果たせる。ただし issue と設計書のテーブル定義が `moderation_flag = 2`
を前提にしており、管理画面で「通報時点で相手が何を言っていたか」を一目で分けられなくなる。

### 案C: 通報者だけを退出させ、会話は続ける

誤った通報や嫌がらせ目的の通報で、3 人ルームの残り 2 人の会話が止まることはない。ただし
2 人ルームでは相手が 1 人残るだけで会話は `CHAT_REJOIN_GRACE` 後に終わり、結果は同じ。
3 人ルームでは、通報された発言者が残った 1 人と会話を続けられてしまい、保護にならない。
退出はもともと画面から常にできる。

### 案D: report が conversations / messages を直接 UPDATE する

呼び出しが 1 段減る。ただし CONTRIBUTING.md の「他モジュールのテーブルに直接クエリを投げない」
に真正面から反し、ADR-0010 で決めた書き込みの分担も崩れる。

## 影響

- 3 人ルームでは、1 人の通報で残り 2 人の会話も終わる。通報を会話終了の手段として乱用する
  利用者がいても、得られるのは退出と同じ結果で、記録は `reports` に残る。
- 通報された側にも「通報があった」ことが伝わる。匿名で相手に連絡する手段が無いため
  報復の経路は無く、抑止として働く側面を取った。
- 通報の瞬間に `chat` の書き込みバッファ（最大 `DefaultWriteInterval`）に残っていた
  メッセージは `0` のまま記録される。会話ごと `is_flagged` で保持されるので消えはしない。
- 見直す条件: 誤通報で 3 人ルームが止まる苦情が目立つようになったら、案C（通報者だけ退出）
  を再検討する。
