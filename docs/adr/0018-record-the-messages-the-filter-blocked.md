# ADR-0018: ブロックしたメッセージも記録する

- ステータス: Accepted
- 日付: 2026-09-09
- 関連 issue: YOSUKE-129

## 文脈

一次フィルタは、辞書に当たったメッセージを相手に届けずに送信者へ返す（設計書 第4章）。
このとき本文をサーバーに残すかどうかを決める必要がある。

- `messages.moderation_flag` は `0:問題なし 1:NG検知 2:通報あり` として既にある（設計書 4.1）。
- 辞書の初期セットは誤検知を含み、運用しながら語を足したり止めたりして調整する
  （[ADR-0004](0004-ng-word-dictionary-in-database.md)）。調整の材料は「実際に何を止めたか」。
- 繰り返し問題を起こす利用者への制裁は通報と `banned_identifiers` が担う
  （[ADR-0016](0016-block-a-participant-in-the-browser-only.md)）。
- 会話ログの保持期間は 90 日で、`retention` モジュールが消す（設計書 第5章）。
- 管理画面はまだ無く、誤検知でブロックされた利用者を個別に戻す手段が無い（YOSUKE-131）。

## 決定

ブロックしたメッセージも `messages` に `moderation_flag = 1` で記録する。部屋には配信せず、
送信者には届かなかったことだけを返す。繰り返し違反は、この記録を `sender_token` で数える。
実行時に違反回数のカウンタを別に持つことはしない。

## 検討した代替案

### 案A: ブロックしたメッセージは記録しない

止めた本文をサーバーに残さずに済む。ただし誤検知を直す材料が何も残らない。
「どの語が何を止めたか」が分からないまま辞書を触ることになり、ADR-0004 が前提にしている
チューニングが成立しない。

### 案B: 送信者ごとの違反カウンタを Redis に持ち、閾値を超えたら送信を止める

繰り返しの荒らしをその場で止められる。ただし誤検知を含む辞書で自動的に制裁を掛けると、
巻き込まれた利用者を戻す手段が今は無い。カウンタは Redis が飛べば消えるため、
後から数え直す記録としても使えない。

### 案C: ブロックしたメッセージを専用のテーブルに記録する

通常のログと混ざらない。ただし `moderation_flag` が既にその区別を持っている。
テーブルを増やすと 90 日削除の対象も増え、`retention` が二重になる。

## 影響

- 送信者には「届かなかった」とだけ返るが、本文はサーバーに残る。保持期間は会話ログと
  同じ 90 日で、専用の扱いはしない。
- `moderation_flag = 1` だけでは、配信されたメッセージと止めたメッセージを区別できない。
  区別が必要になったら、設計書 4.1 の値の定義ごと見直す。
- ブロックしたメッセージの記録に失敗しても、送信者への応答は変えない。届かなかったことに
  変わりはないため。
- 繰り返し違反の集計はまだ実装していない。数えるための記録が残っている状態までが
  この決定の範囲で、集計と制裁は通報対応の側で扱う。
