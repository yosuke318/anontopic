# ADR-0045: セッションの接続元の都道府県を、サーバーが自分で取る GeoLite で判定する

- ステータス: Accepted
- 日付: 2026-11-01
- 関連 issue: YOSUKE-146

## 文脈

- 地域ごとの利用状況と通報の傾向を、広告を出す先の判断と、特定の地域や回線からの荒らしの検知に使いたい（設計書 9 章）。
- 地域による相手の指定や検索は持たない（設計書 3.1 / 3.2）。
- 生の IP アドレスは保存しない。識別子・属性は参加から 180 日で消す（ADR-0037、ADR-0044）。
- 無料で使えるのは MaxMind の GeoLite（City・ASN）。ダウンロードにはアカウントとライセンスキーが要り、1 日 30 回まで。
  使用許諾は、新しい版が出てから 30 日以内に古い版を使うのをやめることと、帰属表示を求める。
- サーバーは ECS Fargate で 2 タスク。prod へのデプロイは毎回承認が要り、イメージはコミットの SHA を名前にする（ADR-0034）。
  NAT インスタンスを通して 443 番に出られる。
- API には ALB から直接届き、接続元の IP は `X-Forwarded-For` の末尾から取れる。

## 決定

- サーバーが起動したときと、その後 1 週間ごとに、GeoLite City と GeoLite ASN を MaxMind から直接ダウンロードしてメモリに読み込む。
  `Last-Modified` が変わっていなければダウンロードしない。取れなければ、判定を飛ばして動き続ける。
  アカウント ID とライセンスキーは SSM パラメータストアに置き、タスクの環境変数で渡す。
- セッションを発行するときに接続元の国・都道府県（ISO 3166-2、日本だけ）・AS 番号を引いてセッションに持たせ、
  ルームが成立したときに `conversation_participants` に書く。matching はそれを記録に渡すだけで、ルームを作るのには使わない。
- 参加から 180 日で、識別子・属性と一緒に消す。通報された会話の参加者の分は残す。
- retention バッチが、過去 7 日分について、国・都道府県ごとの参加者数と、通報された会話の参加者数（通報した人を除く）を
  `geo_daily_stats` に書く。個人に結びつかない数なので、消さずに残す。
- VPN の疑いの判定（`is_suspected_vpn`）と、多重接続の検知に使う `ip_subnet` は、今回は持たない。
- プライバシーポリシーに、使う目的・保管する期間と GeoLite の帰属表示を書く。

## 検討した代替案

### 案A: イメージを作るときにデータベースを入れる

起動時に外へ取りに行かずに済む。ただ、30 日の決まりを守るには毎週作り直してデプロイすることになり、
prod の承認も毎週要る。同じ SHA で中身の違うイメージができ、ロールバックの戻し先も曖昧になる。

### 案B: GitHub Actions が毎週 S3 に置き、サーバーが S3 から読む

MaxMind の 1 日の上限をデプロイの回数と切り離せる。ただ、バケット・IAM・Go の S3 クライアントが増える。
デプロイは 1 日に数回までで、2 タスク × 2 つのデータベースでも上限の 30 回に届かない。

### 案C: DB-IP Lite を使う

アカウントが要らず、帰属表示をすれば商用でも使えると明記されている。ただ、AS 番号の精度は GeoLite のほうが上で、
設計書も GeoLite を前提にしている。

### 案D: 接続元をマッチングに使う（近い地域の人と組む）

設計書 3.1 / 3.2 の「地域による相手の指定」に当たる。採らない。

## 影響

- 1 タスクあたり、メモリを 70 MB ほど多く使う（City が約 60 MB、ASN が約 10 MB）。差し替えの間は一時的に 2 倍になる。
- 起動の直後、ダウンロードが終わるまでに発行したセッションは接続元を持たない。
- 1 日に 7 回を超えてタスクを入れ替えると、MaxMind の上限に当たって判定が止まることがある。止まっても次の週の更新で戻る。
- GeoLite City の都道府県の精度は高くない。地域の数は傾向を見るためのものとして扱う。
- 使用許諾が広告収入のあるサイトでの利用を許していないと分かったら、案C に切り替える。
- 見直す条件: VPN 経由の荒らしが目立ったら、AS 番号の一覧との照合（`is_suspected_vpn`）を別に足す。
