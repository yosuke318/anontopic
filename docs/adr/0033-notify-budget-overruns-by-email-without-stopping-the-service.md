# ADR-0033: 予算の超過はメールで知らせるだけにし、サービスを自動で止めない

- ステータス: Accepted
- 日付: 2026-10-03
- 関連 issue: YOSUKE-138

## 文脈

- 月額予算は 4 万円前後（約 $270）。設計書 6 章-3 は「予算を超えたら新規マッチングの
  受付を自動で止める Lambda 連携」を検討項目に挙げている。
- 費用のほとんどは固定費になっている。Fargate のタスク数は固定（ADR-0029）、RDS と Redis は
  1 台ずつ（ADR-0031）、NAT は 1 台（ADR-0028）。利用量で増えるのは ALB の LCU・外向きの
  通信・ログの取り込みで、同時接続の上限 1,000（ADR-0013）が上限を抑えている。
- 利用量以外で費用が増えるのは、dev の destroy 忘れ（ALB と 1 タスクだけで約 $35/月）や
  設定の誤りのほうがありうる。どちらも新規マッチングを止めても減らない。
- AWS Budgets の費用データは 1 日に数回しか更新されず、超えてから通知まで数時間かかる。
- Budgets のアクションでできるのは、IAM ポリシーや SCP の適用と、指定した EC2 / RDS の
  インスタンスの停止だけで、ECS のサービスやアプリの状態には手が届かない。
- 運用者は 1 名で、アラームも Grafana Cloud もときどき見る程度にとどめる。

## 決定

- アカウント全体の月額予算を AWS Budgets に置き、実際の費用が 50% / 80% / 100% を超えたら
  通知する。予算は prod の Terraform で管理する。
- 予算とインフラのアラームの通知は 1 つの SNS トピックに集め、運用者のメールに届ける。
- 予算を超えても、新規マッチングの受付やサービスは自動で止めない。止めるかどうかは
  通知を見た運用者が決める。

## 検討した代替案

### 案A: Budgets → SNS → Lambda でアプリの受付停止フラグを立てる

アプリが読むフラグ（Redis か SSM パラメータ）、それを読む処理、受付停止の画面、Lambda の
VPC 接続かタスクロールの追加が要る。止めて減るのは利用量で増える一部の費用だけで、
固定費が大半を占める今の構成では、作る手間に見合う効果が無い。

### 案B: Budgets のアクションで RDS を止める

追加の実装は要らないが、サービス全体が止まる。RDS は止めても 7 日で自動的に起動し、
止めている間もストレージの費用はかかる。

### 案C: Slack に通知する（Amazon Q Developer in chat applications）

無料だが、ワークスペースとの連携をコンソールで行う必要がある。1 名運用ではメールで足りる。
同じトピックに購読を足せば、作り直さずに後から加えられる。

## 影響

- 予算を超えたことに気づくのは、通知が届いて運用者がメールを読んだときになる。
  データの更新の遅れと合わせ、半日ほど超えたまま動くことがある。
- SNS の購読は、届いた確認メールのリンクを開くまで有効にならない。
- 予算の値（USD）は為替で円の予算からずれる。大きく動いたら直す。
- 見直す条件: タスク数のオートスケーリングを入れたとき、外向きの通信など利用量で増える
  費用が月額の大半を占めるようになったとき、または利用の急増で予算を超えた月があったとき。
