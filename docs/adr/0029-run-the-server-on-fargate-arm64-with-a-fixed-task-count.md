# ADR-0029: Go サーバーを ECS Fargate（ARM64）の固定タスク数で動かす

- ステータス: Accepted
- 日付: 2026-10-02
- 関連 issue: YOSUKE-136

## 文脈

- 設計書 5 章は WebSocket サーバーを「小型インスタンス 2 台（冗長化）で約 $40」と見積もり、
  6 章でオートスケーリングを使わない固定台数と決めている。開発体制は 1 名。
- 同時接続の上限は 1,000（ADR-0013）。同じ会話の参加者が別のサーバーにつないでも、
  配送は Redis の Pub/Sub を通るため届く。
- ブラウザは切断されると最大 6 回つなぎ直し（待ち時間の合計は約 25 秒）、サーバーは
  `CHAT_REJOIN_GRACE`（既定 30 秒）の間は会話を終えない（ADR-0011）。
- プライベートサブネットの外向き通信は NAT インスタンス 1 台を通る（ADR-0028）。
- 東京リージョンのオンデマンド単価で、2 台を 730 時間動かしたときの月額は次のとおり
  （EC2 は ECS 最適化 AMI の既定のルートボリューム gp3 30GB を含む）。

| 構成 | 2 台の月額 | 常に使える CPU / メモリ（1 台） |
| --- | --- | --- |
| Fargate ARM64 0.25 vCPU / 0.5 GB | 約 $18 | 0.25 vCPU / 0.5 GB |
| Fargate ARM64 0.5 vCPU / 1 GB | 約 $36 | 0.5 vCPU / 1 GB |
| EC2 t4g.micro | 約 $22 | ベースライン 0.2 vCPU / 1 GB から OS と ECS エージェントの分を引いたもの |
| EC2 t4g.small | 約 $37 | ベースライン 0.4 vCPU / 2 GB から同上 |

## 決定

- Go サーバーは ECS Fargate の ARM64 で動かす。タスクは 0.25 vCPU / 0.5 GB、
  prod は 2 タスク、dev は 1 タスクで固定する。
- ALB で HTTPS / WSS を終端する。アイドルタイムアウトはサーバーの ping 間隔（30 秒）より
  長い 120 秒、登録解除の遅延は 300 秒にする。ヘルスチェックは `/healthz` を使う。
- デプロイは新しいタスクがすべて正常になってから古いタスクを止める（最小 100% / 最大 200%）。
  古いタスクの WebSocket は登録解除の遅延が過ぎると切れ、ブラウザが新しいタスクに
  つなぎ直して会話に戻る。
- Terraform はタスク定義とサービスを作るが、サービスが使うリビジョンは追わない。
  イメージの差し替えはデプロイ側で新しいリビジョンを登録して行う。

## 検討した代替案

### 案A: EC2（t4g）に ECS で載せる

常に使える CPU で比べると Fargate より安くならない。t4g.micro は ENI が 2 つでタスクを
1 つしか awsvpc で置けず、デプロイ中に新旧のタスクを並べる余裕もない。AMI の更新と
OS のパッチも自分で持つことになる。

### 案B: EC2 に ECS を使わずコンテナを直接動かす

費用は案A と同じで、デプロイ・入れ替え・ALB への登録を自分で組むことになる。

### 案C: Fargate Spot

約 7 割安いが、2 分前の通知で止められ、2 タスクが同時に止まることもある。止まるたびに
すべての WebSocket が切れる。

### 案D: x86_64 の Fargate

ARM64 より約 25% 高い。Go はクロスコンパイルでき、ARM64 にする手間はほとんどない。

### 案E: 登録解除の遅延を最大（3,600 秒）にする

切れる会話は減るが、デプロイ 1 回に 1 時間かかる。切れてもつなぎ直しで会話に戻れるため、
待つ利点が小さい。

## 影響

- ALB は設計書 5 章の見積もりに入っていない。固定費 約 $18、LCU 約 $8（egress の見積もりから
  処理量を 1.3 GB/時 とした場合）、パブリック IPv4 2 つで 約 $7 の計 約 $33/月 が増える。
  Fargate が見積もりより約 $22 安いため、差し引き約 $11 の増額になる。
- dev も動かしている間は ALB と 1 タスクで 約 $35/月 かかる。
- タスクの起動には NAT インスタンスが要る（ECR の認証・ログ・秘密の読み出し）。
- デプロイのたびに、続いている会話はつなぎ直しの間（数秒）メッセージを送れない。
- Terraform でタスク定義を変えても、次のデプロイまで動いているタスクには反映されない。
- 見直す条件: 負荷試験（YOSUKE-144）で CPU やメモリが足りなければ 0.5 vCPU / 1 GB に上げる。
  1 年以上同じ構成で動かすと決まったら Compute Savings Plans を検討する。
