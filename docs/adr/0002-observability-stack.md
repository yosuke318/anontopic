# ADR-0002: 監視を CloudWatch・Performance Insights・Grafana Cloud の 3 層で構成する

- ステータス: Proposed
- 日付: 2026-08-21
- 関連 issue: YOSUKE-138, YOSUKE-144

## 文脈

- インフラの月額見積もりは約 $280（≒ ¥4.2 万）で、予算目標をほぼ使い切っている。
  監視のために足せる恒常費用はほぼ無い。
- 見たい対象が 3 層に分かれる。
  1. インフラの死活とコスト（CPU、接続数、予算消化）
  2. DB のクエリ単位の遅さ
  3. アプリ固有の指標（同時接続数、マッチング待機時間、NG ワード検知率）
- アプリ層の指標はトピック × ルーム種別という次元を持つため、メトリクス 1 個ごとに
  課金される仕組みに載せると、細かく測るほど費用が上がる。
- 会話ログは原則 90 日で削除し、通報された会話のみ長期保持する。発信者情報も
  法対応の枠組みで統制する必要があるため、これらを外部サービスに預けたくない。

## 決定

3 層に分け、いずれも追加費用が発生しない範囲で構成する。

| 層 | 使うもの |
| --- | --- |
| インフラのメトリクス・アラーム・予算アラート | CloudWatch + AWS Budgets |
| DB のクエリ単位の分析 | RDS Performance Insights（無料の 7 日保持） |
| アプリのメトリクスとダッシュボード | Grafana Cloud Free（10k アクティブ series、保持 14 日） |
| 負荷試験 | k6（Grafana Cloud Free の 500 VU 時間/月） |

アプリは Prometheus 形式で `/metrics` を公開し、Grafana Alloy が収集して remote write する。
**チャット本文、session_token、生の IP アドレスは外部の監視サービスに送らない。**

## 検討した代替案

### 案A: Datadog

2 ホストで Infrastructure Pro が $30/月、APM を足すと $92/月。RDS と ElastiCache は
ホスト課金の対象外なので想定より安いが、予算枠が埋まっているため恒常費用として載らない。
無料プランは保持 1 日で、後から傾向を追えず目的を満たさない。

負荷試験の期間だけオンデマンド（$18/ホスト）で入れて捨てる使い方は、将来の選択肢として残す。

### 案B: すべて CloudWatch に寄せる

インフラと同じ場所に集まる利点がある。ただしカスタムメトリクスは $0.30/個/月
（最初の 1 万件）で、トピック 8 × ルーム種別 2 × 指標 4 種なら 64 メトリクスで $19/月。
マッチング待機時間を細かい粒度で見たいほど高くなり、**測るのを我慢する方向に力が働く**。
待機時間の許容上限はこれから実データで決める項目なので、そこに制約がかかるのは避けたい。

### 案C: Prometheus + Grafana を自前で EC2 に立てる

費用はインスタンス代だけで済むが、監視対象と同じ障害に巻き込まれる。
1 名運用で監視基盤そのものの面倒を見る時間は取れない。

## 影響

- 収集エージェント（Grafana Alloy）のコンテナが 1 つ増える。小型インスタンス 2 台に載る
  範囲だが、リソース消費はゼロではない。
- Prometheus のヒストグラムは bucket ごとに series を消費する（1 つあたり bucket 数 + 2）。
  トピック別にヒストグラムを持つと 10k の枠を圧迫するため、ラベルの次元は最初に決める。
- Grafana Cloud Free はログイン可能なユーザーが 3 人まで。運用者が増えたら有料プラン
  （$19/月〜のプラットフォーム料金 + 従量）になる。
- ステータスを Proposed に留めているのは、実装が M3 で、それまでに各サービスの無料枠の
  条件が変わりうるため。RDS Performance Insights は AWS が Database Insights に再編中で、
  無料で使える保持期間の条件は実装時に確認が要る。確認して構成が成立したら Accepted にする。
- 見直す条件: 広告収入で予算枠が広がった場合、または Grafana Cloud Free の series 上限に
  当たった場合は、Datadog を含めて再検討する。
