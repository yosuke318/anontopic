# ADR-0016: ブロックはブラウザの中だけで完結させる

- ステータス: Accepted
- 日付: 2026-09-06
- 関連 issue: YOSUKE-128

## 文脈

チャットルーム画面にはブロックボタンを常設する（設計書 第7章）。通報
（[ADR-0015](0015-report-a-conversation-rather-than-a-participant.md)）とは別に、
その場で相手の発言を見えなくする手段を持たせる。

- 会話は短命で、参加者が居なくなってから `CHAT_REJOIN_GRACE` を過ぎると終わる
  （[ADR-0011](0011-end-a-conversation-after-a-rejoin-grace.md)）。ブロックを持ち越す
  相手が、会話が終わった後には存在しない。
- 参加者を指す識別子は会話ごとの参加者番号だけで、次の会話では別の人を指す。
- 属性や相手を指定して会話相手を選ぶ機能は持たない（要件定義書 3.1）。
  「この人とは二度とマッチングしない」はその指定に近づく。
- 繰り返し問題を起こす利用者への対処は、通報と BAN（`banned_identifiers`）が担う。

## 決定

ブロックは、その会話を開いているブラウザの中だけで持つ。ブロックした参加者の発言は
本文を伏せて表示し、サーバーには何も送らない。画面を閉じればブロックも消える。

## 検討した代替案

### 案A: ブロックをサーバーに記録し、以後マッチングしない

「二度と会いたくない」に応えられる。ただし相手を指す安定した識別子が無く、
記録できるのはセッショントークンか IP ハッシュになる。セッションは短命で作り直せるため
効かず、IP ハッシュは同じ回線の無関係な利用者まで巻き込む。マッチングから特定の相手を
除外する仕組みは、相手を指定する機能に近づくため 3.1 の方針とも合わない。

### 案B: ブロックを通報として扱う

ボタンが 1 つで済む。ただし「不快なので見たくない」と「規約違反を運営に報告する」は
別の行為で、通報の件数に見たくないだけの操作が混ざると、制裁の判断に使えなくなる。

### 案C: ブロックした相手の発言をサーバー側で配信しない

配信量は減るが、部屋の全員に同じイベントを流す前提（asyncapi.yaml）が崩れ、
参加者ごとに配信内容を持つことになる。得られるものに対して仕組みが重い。

## 影響

- 読み込み直すとブロックは外れる。会話をまたいで持ち越すこともない。
- ブロックしても相手には何も伝わらず、相手の画面は変わらない。
- 見たくない相手が居続ける場合の最終手段は退出になる。退出の導線を同じ画面に
  常設しているのはそのため。
