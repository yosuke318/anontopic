# ADR-0035: フロントエンドは ECS Fargate の 1 タスクで動かし、CloudFront から配る

- ステータス: Accepted
- 日付: 2026-10-05
- 関連 issue: YOSUKE-140

## 文脈

- 設計書 5 章の費用表に Next.js のホスティング費用が入っていない。月額予算は 4 万円前後
  （約 $270）で、表の合計は約 $245。
- `/topics` と `/waiting` はリクエストごとにサーバーで描画し、Next.js のサーバーが API に
  届く必要がある（ADR-0014）。静的に書き出せるのは LP と紹介ページだけ。
- 収益は AdSense を前提にしている。Vercel の Hobby プランは商用利用を認めていない。
- API・RDS・Redis・NAT は東京リージョンの 1 つの AZ に寄っていて、冗長化していない
  （ADR-0028、ADR-0031）。AWS 側が止まればサービスも止まる。
- ALB は API のドメイン（`api.<domain>`）で HTTPS を終端している（ADR-0029）。
- Fargate ARM64 の 0.5 vCPU / 1 GB は 1 タスクで月約 $18。CloudFront は毎月 1 TB の転送と
  1,000 万リクエストまで無料。
- `NEXT_PUBLIC_` で始まる値と、静的に生成するページ（OGP・canonical・`sitemap.xml`）の
  絶対 URL は、`next build` のときに埋め込まれる。
- 開発体制は 1 名。

## 決定

- Next.js を `output: "standalone"` のコンテナにし、API と同じ ECS クラスターの Fargate
  ARM64 で動かす。prod は 0.5 vCPU / 1 GB、dev は 0.25 vCPU / 0.5 GB で、どちらも 1 タスクに固定する。
- サイトのドメインは prod が `<domain>`、dev が `dev.<domain>` とし、CloudFront で配る。
  オリジンは API と同じ ALB で、ALB の証明書に合うよう API のドメインを指す。
- CloudFront はオリジンへの要求にヘッダー `X-Anontopic-Route: web` を付け、ALB はこの
  ヘッダーが付いた要求だけをフロントエンドのターゲットグループに送る。
- CloudFront は HTML をキャッシュしない。キャッシュするのは、ファイル名に内容のハッシュが
  入る `/_next/static/*` だけにする。
- フロントエンドのイメージは環境ごとにビルドする（ADR-0034 の「1 回だけビルドする」の例外）。
  同じコミット・同じジョブで、渡す `NEXT_PUBLIC_` の値だけを変える。
- Next.js のサーバーは API を公開ドメイン（`API_BASE_URL=https://api.<domain>`）で呼ぶ。

## 検討した代替案

### 案A: Vercel Pro（$20/月）

費用は ECS とほぼ同じだが、請求・ログ・デプロイの仕組みが AWS と別になる。AWS が止まれば
API も止まるため、フロントエンドだけを別の基盤に置いても可用性は上がらない。

### 案B: S3 + CloudFront に静的に書き出す（`output: "export"`）

月 $1〜3 で最も安いが、ADR-0014 で決めた `/topics` と `/waiting` のサーバー描画と両立しない。

### 案C: Lambda + CloudFront（OpenNext）

無料枠にほぼ収まる。ただし OpenNext による変換と Lambda まわりの構成を 1 名で保守することになり、
Next.js の更新への追従も OpenNext を待つ。コールドスタートも入る。

### 案D: Amplify Hosting

従量課金で、この規模なら月 $15〜20。ECS と同程度だが、ビルドとデプロイの仕組みが API と別になる。

### 案E: 2 タスクで冗長化する

月 $18 増えて合計が予算を超える。ADR-0031 と同じく、止まったら立て直す方を取る。

### 案F: サイトのドメインの Host ヘッダーで ALB に振り分ける

ALB の証明書にサイトのドメインを足し、CloudFront のオリジンの名前もそれに合わせる必要がある。
ヘッダーで振り分ければ、API の証明書とドメインをそのまま使える。

## 影響

- 月額は約 $20（タスク約 $18、ログと ECR が少し）増え、設計書の合計は約 $265 になる。
  予算の $270 にほぼ張り付く。
- タスクが 1 つしか無いため、落ちると ECS が置き換えるまでの数分間、サイトは応答しない。
- dev で確かめたフロントエンドのイメージと prod のイメージは、埋め込んだ値が違う。
- デプロイ中は新旧のタスクが並ぶ。新しい HTML が指す `/_next/static/*` を古いタスクが受けると
  404 になりうる。CloudFront にはこの 404 を残さない。
- Next.js のサーバーから API への呼び出しは NAT インスタンスを通る。NAT が止まると `/topics` は
  トピックを出せず、読み込み直しの案内に替わる（ADR-0014）。
- フロントエンドにもアラーム（CPU・メモリ・正常なタスクの有無・5xx）を置く。ALB 自身が
  返す 5xx はターゲットグループごとに分かれないため、API の 5xx のアラームにも入る。
- ドメインを取得するまでは、フロントエンドの環境も CloudFront も作らない。
- 見直す条件: タスクの CPU かメモリが張り付いたとき、収益がサイト停止の数分に見合う額に
  なったとき（2 タスクにする）、または LP の配信をエッジに寄せたくなったとき（HTML のキャッシュ）。
