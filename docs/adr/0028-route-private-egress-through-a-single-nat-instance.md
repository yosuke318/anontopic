# ADR-0028: プライベートサブネットの外向き通信を 1 台の NAT インスタンスに通す

- ステータス: Accepted
- 日付: 2026-09-28
- 関連 issue: YOSUKE-135

## 文脈

- 月額予算は 4 万円前後で、設計書 5 章の見積もり（約 $280）でほぼ使い切っている。
  見積もりに NAT の費用は入っていない。
- アプリ・RDS・ElastiCache はプライベートサブネットに置き、外から直接届かないようにする。
- アプリがプライベートサブネットから外に出る先は、ECR（イメージの取得）、CloudWatch Logs、
  Secrets Manager などの AWS API と、Grafana Cloud（ADR-0002 の remote write）。
  Grafana Cloud は AWS の外にあり、VPC エンドポイントでは届かない。
- 利用者からの通信は ALB を通って入り、NAT は通らない。NAT を通るのはアプリが自分から
  始める通信だけで、量は少ない。
- 東京リージョンの時間単価での月額の概算は次のとおり。

| 構成 | 月額 |
| --- | --- |
| NAT Gateway（1 AZ） | 約 $45 + 処理量 $0.062/GB |
| NAT Gateway（AZ ごと、2 台） | 約 $90 + 処理量 |
| インターフェイス型エンドポイント（1 サービス × 2 AZ） | 約 $20 |
| NAT インスタンス（t4g.nano + パブリック IPv4 + EBS 8GB） | 約 $8 |

## 決定

- 外向きの通信は、パブリックサブネットに置いた NAT インスタンス（t4g.nano、Amazon Linux 2023）
  1 台に通す。プライベートサブネットは AZ にかかわらず同じルートテーブルでこの 1 台を向く。
- S3 のゲートウェイ型エンドポイントは無料なので常に作る。ECR のイメージのレイヤーは
  S3 から取得されるため、イメージの取得の大半は NAT インスタンスを通らない。
- インターフェイス型エンドポイントは作らない。network モジュールの
  `interface_endpoint_services` に名前を渡せば作れるようにしておく。

## 検討した代替案

### 案A: NAT Gateway

運用の手間がなく、可用性も AWS が持つ。ただし 1 台でも月 $45 で、見積もりの 16% を
アプリが自分で始める少量の通信のために使うことになる。AZ ごとに置けば $90 になる。

### 案B: NAT を置かず、インターフェイス型エンドポイントだけで AWS API に届かせる

ECR（api / dkr）・CloudWatch Logs・Secrets Manager の 4 サービスで約 $80/月と NAT Gateway より高い。
しかも Grafana Cloud に届かないため、NAT 自体を無くせない。

### 案C: アプリをパブリックサブネットに置き、パブリック IP で直接外に出る

NAT は要らなくなる。ただしアプリへの到達を防ぐのがセキュリティグループだけになり、
設定を 1 つ誤るとアプリが直接インターネットにさらされる。タスクごとにパブリック IPv4 の
料金もかかる。

### 案D: 公開されている NAT インスタンス用の AMI（fck-nat など）を使う

設定済みで手間は減る。ただし第三者の AMI を信頼することになり、やることは IP 転送と
MASQUERADE の数行で、自分で書いても手間は変わらない。

## 影響

- NAT インスタンスが単一障害点になる。止まると ECR からの取得・ログの送信・メトリクスの
  送信が止まり、新しいタスクを起動できなくなる。ALB 経由の利用者の通信と、アプリから
  RDS / ElastiCache への通信は止まらない。EC2 の自動復旧に任せ、死活の監視は monitoring の
  issue で足す。
- AZ-c のアプリの外向き通信は AZ-a の NAT インスタンスを通るため、AZ 間の転送料金
  （$0.01/GB）がかかる。量が少ないので無視できる。
- OS の更新は自分で行う。AMI は `ignore_changes` で固定しているため、更新するときは
  `terraform apply -replace` で入れ替える。入れ替えの間は外向きの通信が止まる。
- 見直す条件: NAT インスタンスの停止で障害が起きたとき、または予算に余裕ができたときは
  NAT Gateway に切り替える。特定の AWS API の通信量が多いと分かったときは、そのサービスだけ
  `interface_endpoint_services` に足す。
